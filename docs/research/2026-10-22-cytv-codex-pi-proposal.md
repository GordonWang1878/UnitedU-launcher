## 2. 安装前的信任与失败处理

1. 预先固定官方 HTTPS 清单来源，禁止 Agent 临时改用第三方清单。核查 APK URL 的来源约束，下载的 hash 必须与所用官方清单一致。
2. 双渠道都取得有效清单时，比较 `versionCode`、`versionName`、`minSdk`、`sha256`；不要求两个 `apkUrl` 相同。身份冲突停止，不猜选一份。顺序发布或缓存差异也必须如实报告，不能伪称已核对一致。
3. 只有一个官方渠道可达时，doctor 报告未完成双渠道交叉检查；指引取得安装用户明确确认后可继续。严格双渠道可作为选项，不是默认依赖。已有异常响应、非法来源或 hash 错误不能降格为普通不可达。
4. 这验证的是文件与受信发布清单的一致性。官方发布流程预先检查 APK 身份与签名；客户端不宣称用 Python 标准库独立验过 APK 证书。两份清单来自同一发布流程，不是独立信任根。
5. 现有清单未包含包名；包身份依据是固定的官方产品来源与发布脚本的包名校验，报告必须写明依据，不伪称从清单或 APK 本地解析到包名。版本身份来自清单，文件 hash 客户端实算，设备已有版本来自设备查询。
6. 目标设备/用户不明确、下载完整性不能确认、已装版本查询不足以排除降级等关键未知阻止安装。输入源、真实遥控器表现等非关键未知记为待验证，不阻止普通 APK 安装。
7. 已装包的签名兼容若不能提前可靠判断，报告为未知；可在确认后尝试正常覆盖安装，由 Android 包管理器检查。失败停止并保留数据，禁止以卸载重装绕过冲突。该边界不能包装成已预验签名兼容。
8. 网络不可达或额外验证工具缺失时可以介绍其他正常安装路径；hash 不符、身份冲突、来源异常时不能建议用户手动安装同一个可疑文件。

## 3. 并行真机试点

获准发布招募后，招募 3–5 位自愿者，以至少三台不同条件完整报告、其中至少两台国行为目标。海信先行是因为可以用现有稳定版验证冷启动假设，品牌规模只作背景；其次小米的相关实体按键场景和海外 Google TV。不以品牌出货份额估算新增覆盖。

记录安装、服务启用/绑定、实体按键/键码/目标窗口/最终行为、待机/屏保、至少两次正常冷启动，以及 Wi-Fi、Cast、输入切换和专用键等相关副作用。无法读取的键码等字段标未知并说明，不编造；不得为了取证擅自修改系统组件。下一次获准正式更新后的保持另行追踪，不为验收制造更新。

每个失败提供证据、当前定位、已排除项与下一步，根因不明允许为未解决项。目标是新增至少一条经验证的可用路径；达不到时交付可复用的阻断证据，明确未达到目标。

维护者投入约 3 人日，测试者等待另计。启动后两周检查样本与证据；不足时换渠道或缩小范围，不无限等待、不虚报完成。不做试点会让现有功能能否解决真机问题继续未知；采样成本有限，不以“尚无收益证据”否决采样本身。

## 4. 有复现证据后择优研究/修复

最多 4 人日，择优一至两项，候选为：实体 HOME 发 ALL_APPS 的兼容、缺标准 TIF 时的已验证厂商输入面板入口、重启接管恢复。前两项必须有设备复现、可关闭、修复前后差异及基线无回归；不把上游存在键码映射自动解释成本产品必然失败。

自动恢复是研究候选，不预先承诺发布：

- 单独授予相关权限及应用内独立开关是必要条件，不能替代对后来主动关闭的处理；关闭开关或撤销授权后不写回，不修改其他服务。
- onUnbind 和心跳只是候选信号，不能直接判定关闭原因。研究覆盖主动关闭、临时解绑、进程退出、重启、厂商再次清除及启动广播不送达。模拟器通过不能证明跨厂商有效。
- 无法可靠处理用户主动关闭时，本轮不发布自动写回，交研究结论与人工恢复指引；不能回落为“曾开启恢复开关就写回”。
- “系统关闭只暂时有效，永久关闭需到应用内操作”属于另一份用户控制语义提案，本稿不认可、不授权实施。
- 新增广泛权限、组件或持久化语义先做用户控制与回退兼容审查，相关产品取舍由 Gordon 决定；新增字段/组件遵守现有数据向下兼容要求。正式修复经获准的 release.sh Beta 发版与测试者验收，不直接往 Gordon 电视装开发包。

推迟这些修复会保留具体设备的失败路径；因此以试点证据择优，不能只以维护期为由拒绝，也不能未经复现泛化到所有设备。研究可得出不发布，不能把这种结论算作已经修好。

## 5. 顺序、成本与独立决策

建议获准开工后先起草 A1 和招募材料；A2 与 A4 完成后由 A3 验收；试点和 A5 并行，不依赖购买设备；复现后择优 C。启动后第 2–3 周复盘样本、故障与是否值得继续。第 1–5 天是工程计划窗口，不是交付保证。

估算：必交付 6 + 试点 3 + 修复最多 4 + 获准的上游沟通/专用设备准备预留 1 = **最多 14 人日提案上限**。预留未发生不消耗；设备费用、模型调用费用、测试者和审批等待另计；没有可靠实际耗时数据，不把估算当已测定成本。预计超出就重新取舍，优先删便利和抽象，不删必要校验与失败处理。

以下为后续独立决策点，不是本轮要求 Gordon 回答的问题，也不表示已授权：

1. 实施范围与工程预算。
2. README、模板、工具、指引及兼容索引等材料对外发布；招募文案与渠道。内部准备与获准的测试可以先行，不因外发审批而全部搁置。
3. 是否采购专用 Google TV 盒、价格上限与该机开发安装权限；不采购不阻塞志愿者试点。
4. 广泛权限与自动恢复的用户控制语义、具体 Beta 发布。
5. 有试点证据后，是否向 CYTV 提窄议题：保留原厂组件、安装正式 UnitedU、使用自身接管，不承诺继承 CYTV Launcher 的按键修复。

## 6. 本轮推迟与再评估

推迟通用 debloat 清单/执行器、自动停用原厂 HOME、改包名/关闭安装校验、自建 ADB 客户端/任意配置引擎、主题包/Module Cards/全面多语言/Lite 版。

代价：暂不解决必须修改系统组件的设备、不立即取得上游主题和模块生态、暂不覆盖新增语言和极小体积需求。优先把预算用于可验证安装与接管覆盖；检查点根据精确型号/固件和真实需求重估。高级系统交接实验须另有授权及恢复设计，不因复盘自动开工。
