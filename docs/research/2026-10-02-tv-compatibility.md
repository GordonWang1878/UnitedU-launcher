## 一页结论

**能不能用,主要不取决于 Android 版本,而取决于厂商放不放:能不能装第三方 APK、HOME 键能不能交给第三方桌面。**Android 版本只划一条硬线:Android 9(API 28)以下装不上。

## 1. 决定能不能用的三道关

### 关 1:装得上吗

- **Android 9(API 28)是硬门槛**:minSdk 28,低于它系统直接拒装。
- **`uses-feature android.software.leanback required=true` 不影响侧载**:Android 安装时不检查 uses-feature,只有商店拿它过滤(developer.android.com 原文,一手,高)。
- **32 位用户空间没问题**:APK 里唯一的 .so(androidx 的)四种 ABI 都有,且已 16 KB 对齐;国产电视 64 位芯片跑 32 位系统很普遍(小米、TCL、酷开、索尼都有报告)。
- **厂商拦截**:TCL 拦声明 HOME 的 APK;长虹拦 U 盘 APK;创维装应用要过「应用圈」白名单(新系统才有「允许安装未知来源」);小米未知来源按应用授权、ADB 每次开机要重开;华为 MateTV 不再运行 APK。

### 关 2:能当桌面吗(HOME 键归谁)

- **AOSP 的规则**(第 3 部分,源码直读 + 模拟器实测,高):系统解析 HOME 时,候选的 intent-filter 优先级不同就直接取最高者,不看 HOME 角色或用户的选择;**侧载应用的优先级会被系统压成 0**。所以只要厂商给原厂桌面更高的 HOME 优先级,第三方桌面在任何 Android 版本上都抢不到 HOME 键。
  - 实测:Google 两个 Android 14 镜像里原厂桌面(`launcherx` / `tvlauncher`)的 HOME 优先级都是 2,`cmd package set-home-activity` 把 HOME 角色改成 UnitedU 之后,HOME 键仍回 Google 桌面。CLAUDE.md 里「`set-home-activity` 带 `--user 0` 返回 Success 却不生效」的根因其实就是这个。
  - 国行 A95L 上所有桌面优先级都是 0,HOME 角色说了算——这就是 UnitedU 在索尼上能当桌面的原因。
- **国产厂商的做法**更直接:创维把默认主页写死在配置文件、HOME 走私有 intent;小米 2021 起固件强制回 PatchWall;TCL 只允许在自家两个桌面间切换。
- **「开机自启」不等于「默认桌面」**:当贝桌面在锁 HOME 的品牌上用的是「开机后把自己拉起来」,HOME 键照样回厂商桌面;小米澎湃 OS 据称连第三方开机自启也禁了(低)。
- **AOSP 电视设置 9–16 都没有「主屏幕应用」页**;Android 10 起由权限控制器接走 `HOME_SETTINGS`(手机样式的默认桌面页)。在 GMS 电视上用户能在这个页面勾 UnitedU,但勾了也不改变 HOME 键;在 Android 9 的 AOSP 电视上这个入口会打开一个当场关掉的空页。

### 关 3:功能完整吗

| 能力 | 结论 |
|---|---|
| 输入源页(标准 TIF) | 任何 leanback 设备都有 TvInputManager,但**输入列表全靠厂商实现**;切换要由系统 TV 应用接直通 URI(AOSP 是 `com.android.tv`,索尼是 `com.sony.dtv.tvlin`)。国产四大品牌**都没查到**标准透传可用的证据,小米走私有 `com.xiaomi.mitv.tvplayer/.ExternalSourceActivity`;当贝桌面的信号源切换是按品牌逐个适配私有接口。**在多数国产电视上,输入源页大概率是空的(只有「返回」)** |
| 系统屏保(选 UnitedU) | AOSP / GMS 版 Android TV 的屏保列表会列出第三方屏保(模拟器实测 UnitedU 在列表里);**Google TV 只剩 Ambient,第三方屏保只能 adb 写 `screensaver_components`**;华为只能选自带的;其余国产品牌未查到 |
| 「显示在其他应用上层」(更新后拉回桌面要用) | AOSP 各版本都有这个特殊权限页,且明文把电视排除在「低内存设备禁用」之外;三套实测环境都有;国产品牌未查到。Android 9 没有后台启动限制,本来就不需要它 |
| 应用内安装更新 | 需要按应用打开「安装未知应用」;AOSP 各版本都有;小米要单独授权;长虹 / TCL 的安装拦截同样适用 |

### 其他会影响用户的发现

- **UnitedU 只声明了 `LEANBACK_LAUNCHER`,没有普通 `LAUNCHER`**。国产厂商桌面的「我的应用」按哪个分类列应用,没查到;在 HOME 被锁的品牌上,如果厂商桌面不列只带 `LEANBACK_LAUNCHER` 的应用,用户连打开 UnitedU 的入口都没有。(待实机验证;改起来只是清单里多加一个分类。)
- **广电「开机进直播」**:2023-11 广电总局的推荐性标准要求有线电视终端默认开机进全屏直播;2026-06 发布 GY/T 428-2026(一体化电视);华为 HarmonyOS 4.0 已加「开机默认进直播」。新机开机后最先出现的可能是直播画面,而不是任何桌面。
- **Android TV 版本线**:9 / 10 / 11 / 12 都有消费设备;13 只有开发者版;14 于 2024 年发布;15 跳过;16 于 2025-05 发布说明与模拟器,截至 2026-08-31 没查到任何消费设备推送。所以 targetSdk 35 那批行为变化(后台启动收紧等)在今天的电视上都还没生效。开发者验证(2026-09-30 起)只对手机 / 平板强制,ADB 安装豁免。

## 4. 对 1.0 的建议(待 Gordon 定)

1. **清单里给主 Activity 加普通 `LAUNCHER` 分类**(很小的改动):让 HOME 被锁的品牌(小米新机、创维、华为)的厂商桌面能列出 UnitedU,至少能当普通应用打开。
2. **修 Android 9 上「设置默认桌面」打开空页**(小改):复用屏保入口那套「弹回检测」,检测到空页就提示改用 HOME 键的选择框。
3. **GMS 电视上的提示**:勾了默认桌面 HOME 仍不归 UnitedU 时(`resolveActivity(HOME)` 不是自己),在默认桌面页说明原因与 adb 做法——或者只写进 README 的 FAQ。
4. **README 的定位改窄**:从「索尼 / 小米 / TCL 等」改成「允许更换桌面的国行 Android 9+ 电视,目前验证:索尼」,附兼容表。
5. **更大的取舍,不建议 1.0 做**:①「开机自启」(收开机广播把自己拉起来,学当贝)——能补海信「冷启动回聚好看」、可能补小米 / 创维的开机首屏,但 HOME 键照样回厂商桌面;②给 TCL 出一个不声明 HOME 的构建——能装上,但只是普通应用。

## 5. 待实机验证清单(征集测试时请用户跑)

1. `getprop ro.build.version.sdk`(≥ 28 才装得上)。
2. `adb install` 是否成功;TCL 上带 HOME 的包是否被拦。
3. `adb shell cmd package set-home-activity com.uniteduone.launcher/.MainActivity` 之后,按 HOME 是否进 UnitedU;冷启动(断电)后进的是谁。
4. 厂商桌面的「我的应用」里能不能找到 UnitedU。
5. 输入源页:`TvInputManager` 列出几路输入,按确定能否切过去。
6. 系统屏保列表里有没有 UnitedU;没有时 `settings put secure screensaver_components com.uniteduone.launcher/.UnitedUDream` 是否生效。
7. 「显示在其他应用上层」在电视设置里有没有入口;没有时 `adb shell appops set com.uniteduone.launcher SYSTEM_ALERT_WINDOW allow` 是否可用。
8. 海信:2023 年起的云端风控会不会拦 UnitedU 本身、以及从 UnitedU 打开的应用。
