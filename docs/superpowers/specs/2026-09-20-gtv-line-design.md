# spec:gtv 线 —— 全 app 复刻 Google TV 外观

> **这是什么**:在 main 之外单开一条 UI 线,把 UnitedU 的全部界面换成 Google TV(`launcherx` 1.0.976298245)的外观,做完与现在的 UnitedU 并排比,由 Gordon 挑一套当 1.0。
> **依据**:尺寸与画法来自实测报告 `docs/research/2026-09-20-google-tv-launcherx-measurements.md`;每一项取舍的裁定见 `docs/research/2026-09-20-gtv-vs-unitedu-comparison.md` §D,本文不重复论证,只写落地。
> **对照图**:`docs/screenshots/gtv/`(带 `INDEX.md`)。
> **不变的产品定义**:零广告、零推荐,只有用户自己放上去的应用。外观照搬 Google,**内容与功能仍是 UnitedU 的**。

## §0 不变量(改任何一条之前回来读)

1. **焦点七条铁律照旧全部适用**(`CLAUDE.md`):不用任何可滚动容器、位移自己算 + `wrapContentWidth(unbounded = true)`、焦点落地只信目标自报 `isFocused`、每个浮层自己负责焦点恢复、目标与当前位置每个分量都拆开、守卫与依赖成对出现、不用一次性布尔闩。**本线新增的每一个浮层都要在 CLAUDE.md 的焦点责任表里加一行。**
2. **行尾裁切不等于 0 宽**。Google 的行尾卡是被屏幕右缘裁切、仍正常参与布局(实测宽 74 px 仍可聚焦);铁律 §1 里「被量成 0 宽永远聚焦不到」是父约束夹出来的另一回事。本线**必须继续给行容器加 `wrapContentWidth(Alignment.Start, unbounded = true)`**,靠 `Modifier.offset` 自算位移,靠屏幕边界自然裁切 —— **不能**用 `clipToBounds` 之外的任何约束去实现 peeking。
3. **密度换算**:实测在 1920×1080 @ 320 dpi(density = 2.0)下取得,A95L 的 override 尺寸与密度逐位相同,所有 dp 值 1:1 可用。
4. 本线**不动** main;分支 `gtv`,worktree `.claude/worktrees/gtv`。
5. 不推 GitHub,直到 Gordon 说「推」。

## §1 并存:独立包名(第一个任务)

- `applicationId` = `com.uniteduone.launcher.gtv`,应用名「UnitedU GTV」。
- 与现有 UnitedU 同时装在 A95L 上来回比,**两边设置与图片各存各的**:数据目录随包名天然隔离,`layout.json` / `settings.json` / `titles.json` / `hidden-inputs.json` / `library/` 全部独立,不做任何迁移、不读对方的目录。
- 签名复用 `~/.unitedu/release.jks`(同一把 key 不同 applicationId 可以共存)。
- 这一步单独成一个任务先落地,后面每个任务都能装机对比。

## §3 首页

自上而下:**顶栏(常驻)→ hero 区(纯壁纸,192 dp)→ 应用行 ×1–5**。

- **hero 区什么都不放**(B3),壁纸直接透出来。在我们这里「英雄区」就是壁纸本身。
- **壁纸随整页位移变暗、原地不动(Ruling R45,2026-09-22,取代 R35「壁纸随页面上移」与 R36 的两层方案)**:壁纸单层、不位移,alpha 按整页位移的绝对值从 1 线性降到 0.20——`1 − 0.8 × clamp(|shift| / 192, 0, 1)`(`GtvLayout.wallpaperAlpha`),与卡片行走同一根弹簧逐帧换算。192 dp(= hero 高,`WALLPAPER_FADE_OVER_DP`)是 R35 定的距离;终值 0.20(`WALLPAPER_BROWSE_ALPHA`)是 **R36** owner 定的「留两成壁纸影子」(Google 浏览态是纯黑,这是有意偏离)。静止态(位移 0)全亮、与改动前逐像素相同。被推翻的两版:R35 让壁纸原样跟整页走,下两行时整张图被推出屏幕;R36 两层同图(上层随页面走并淡出、底层原地常驻 20%)在 R42 的小位移下上层淡不完,两份错位副本同时可见,owner 报「残影」。Google 录像里 backdrop 在上下滚动时原地不动,只变暗 / 换图(`docs/screenshots/gtv/22-google-backdrop-static-while-scrolling.jpg`)。
- 应用行从 hero 下面开始,行内卡片 16:9(B8:**不改圆形图标**,banner 优先 → 自定义卡片图 → 无 banner 回落成图标居中 + 纯色底,三条路全保留)。
- **首页取消行标题,行图标进左边距(Ruling R48,2026-09-22,owner 看效果图选 A2 `docs/screenshots/mockups/A2-no-title-icon-in-margin.jpg`)**:owner 原话「可不可以不要行标题?……把行图标留着……图标和应用卡片放在同一行内,纵向居中,放在最左边;不再以标题的形式呈现,只要一个图标,不要文字」。首页不画行标题文字;行图标(方框 `rowIconSize` ~~26~~ → 22 dp,**R50**)画在左边距里,水平中心 29 dp、与本行卡片纵向居中,不随行内横向位移走(整行左移时卡片从图标上方盖过去)。焦点行图标近白 `#E6F2FD`、其余行灰 `#959BA3`(R46 从 Google 浏览态行标题量的两色),灰 ↔ 白与整页位移同一根弹簧(R47),**不缩放**;行名改由图标的 contentDescription 提供给无障碍服务。几何:每行少 32.5 dp(§2.1 / §2.2),行 0 卡片位置不动(~~R42 的可见区间上沿改为「卡顶 − 聚焦溢出」~~ R52 起行 0 钉焦点线、R42 已删;行距 R51 又加回 32 dp)。编辑页不变(仍画行名 13 sp + 20 dp 图标)。这条取代了行标题的整条演进:R40(进入可视区时淡入)→ R43(焦点行放大变亮)→ R46(白 / 灰两态、焦点行 1.78×)/ R47(与位移同一根弹簧)。

**Ruling R34(2026-09-22,Round 9)/ R37(Round 10)——进焦放大时长**:mp4 真实时间戳实测 Google 的进焦放大约 1.2 s(资源 `focused_frame_animator_duration_ms = 1200`,减速型),失焦缩回 150 ms——此前把 150 ms 当成进焦时长是误判,那是失焦的数字。R34 照 1200 ms 做;**R37** 按 owner 手感缩短到 **600 ms**(曲线仍减速型,失焦 150 不变)。终值倍率仍是 1.10(静态截图实测;录像里运动模糊读到的 1.135 不采信)。

**Ruling R47(2026-09-22)——行标题焦点态与整页位移同一根弹簧(R48 起是行图标)**:owner 要求「三层联动」照 Google 做。Google mp4 实测:行标题与页面位移同起同止(约 0.3 s 到 95%),焦点卡在位移刚起步就开始放大、约 0.13–0.17 s 放完;R43 的 300 ms 减速 tween 约 0.14 s 就到 95%,比位移早一倍收尾。改用与浏览位移同刚度的临界阻尼弹簧,标题与位移同起同止;`FOCUS_AFTER_SHIFT_DELAY_MS` 80 与进焦 600 ms 这两个 owner 手感值不动。R48 删掉行标题后,这根弹簧只驱动行图标的灰 ↔ 近白(不缩放)。

**外扩描边不能用 `border` 直接画**(`border` 画在布局框上),要用 `drawBehind` 在框外画,且父容器不能 clip 掉 —— 与铁律 §1 的 `unbounded` 同一类问题,实现时先写一个最小例子验证再铺开。
