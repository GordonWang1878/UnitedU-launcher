# 官方图片资源图库设计

状态：设计与实施计划均已获 Gordon 确认；2026-10-09 已完成本地实现及主要集成验收，等待最终独立评审；证据、未执行项和数据保留例外见 [验收报告](../../design/resource-gallery-acceptance-2026-10-09.md)。日期：2026-10-08。

## 1. 目标与已确认范围

保留 APK 随附的基础壁纸、应用卡片和屏保图片，新增官方在线图库。支持图库的客户端首次需要通过 APK 更新交付；此后在既定清单协议内新增图片只需发布图片和清单，无需再次更新 APK。

Gordon 已确认：

- 同步清单和缩略图，选用时下载原图，下载后离线可用。
- 打开图库自动检查更新，并提供手动刷新入口。
- 首期用静态图片目录和 JSON 清单维护，不建管理后台。
- 三个选图页提供「内置 / 在线图库 / 我的」，在线卡片按应用包名筛选。
- 原图下载校验成功后才应用；失败保留现有选择。新在线屏保由用户主动加入轮播。
- 固定资源 ID 与显示名称、排序分离；下架不删除已下载、正在使用的图片。
- 建议复用现有 R2 托管，图库使用独立目录；先上传全部文件，再更新清单。

首期只支持图片，不扩展在线屏保视频、账号登录、收藏、云端个人同步、付费资源或网页后台。「同步」指官方目录同步，不指用户配置跨设备同步。

## 2. 当前接入基础

- `BuiltinCatalog.kt`：内置分类、身份、三语名称、卡片应用映射、壁纸选择与屏保过滤的纯逻辑。
- `BuiltinImages.kt`：APK assets 枚举、读取和图片解码。
- `ImagePicker.kt`、`PickerCells.kt`：现有选图和遥控器焦点模型。
- `Wallpapers.kt`、`Settings.kt`：壁纸引用和设置持久化。
- 现有屏保播放逻辑：读取本地可播放资源，支持桌面和系统屏保。
- `Update.kt`、`UpdateChecker.kt`：已有 HTTP 下载、SHA-256 校验的实现经验。
- `scripts/release.sh`：已有 R2 静态文件发布路径。

在线资源另建目录与状态，不伪装成 APK assets，也不混入用户上传图库。复用图片解码、展示与卡片应用流程，避免另建播放器。图库下载独立于 APK 更新下载生命周期。

## 3. 托管与清单协议

建议生产目录为 `https://dl.uniteduone.com/gallery/`，清单为 `index.json`；这里只定义目标路径，不表示已经上线。

清单格式版本为 `schemaVersion: 1`，包含递增整数 `revision` 和 `items` 数组。每个资源包含：

| 字段 | 规则 |
|---|---|
| `id` | 全图库唯一、稳定的 ASCII 标识；发布后不得复用为另一张图片 |
| `kind` | `wallpapers`、`cards`、`screensavers` 三选一 |
| `names` | 必须提供 `zh-CN`、`zh-TW`、`en` 三语名称 |
| `order` | 分类内显示顺序；同序按 ID 排序 |
| `thumbnail` | 相对路径、字节数、SHA-256；缩略图用 SDR |
| `original` | 相对路径、字节数、SHA-256、宽高和媒体类型 |
| `packages` | 卡片必须填写非空应用包名数组，其他类型省略 |
| `credit` | 来源与许可说明文字 |

允许同一应用对应多张在线卡片，方便用户挑选；包名精确匹配，不依靠应用显示名称猜测。

文件按内容哈希命名，不覆盖已发布的图片文件。路径必须在图库目录内，拒绝绝对 URL、路径穿越、查询参数和跳转至其他域名。只接受 HTTPS，重定向后的地址同样校验。

建议客户端限制：清单最大 2 MiB、最多 2,000 项、缩略图每张最大 512 KiB、原图每张最大 32 MiB、最长边不超过 8,192 像素。读取过程执行上限，不能只相信清单中的尺寸。上述值为首期实现参数，不是用户设置。

遇到未知格式版本、重复 ID、非法字段或越界路径，拒绝整份新清单并保留上一份有效目录。未知额外字段可忽略。仅原子替换完整验证通过的清单。

## 4. 客户端模块与数据流

职责拆分：

1. **目录模型和解析**：纯 Kotlin 逻辑，验证协议、分类、排序、包名和路径。
2. **图库仓库**：维护有效清单、刷新状态、资源下载状态；向三个选图页提供共享状态。
3. **下载与存储**：受限 HTTP 读取、去重、完整性校验、原子写入，以及磁盘不足处理。
4. **选用接入**：把已验证本地文件交给壁纸、卡片和屏保的现有流程。
5. **发布工具**：检查源图片、生成缩略图和清单、上传文件、最后发布目录。

打开任一选图页时先展示本地内容，同时在后台检查清单。多个页面或 Activity 共用进程级仓库，同一时刻只执行一次刷新；手动刷新也加入这一刷新，不发重复请求。客户端不进行常驻定时同步。

清单使用 ETag 条件请求。304 保留本地目录；200 完整验证后替换。新目录先出现，再按可见区域下载缩略图；不阻塞页面等待全部缩略图。缩略图失败显示占位和重试入口。

## 5. 选图体验与焦点

沿用现有选图页，按「内置 / 在线图库 / 我的」分组，不新增必须登录的独立应用流程。在线卡片只显示当前应用适用的资源。

资源状态包括：未下载、下载中、已下载、失败。选用未下载资源先下载原图；显示进度，支持取消和重试。预览使用原图也必须按需下载；仅预览不改变选用状态。

刷新、缩略图到达和下载完成不得自动抢焦点。用资源 ID 保持当前焦点；当前项目下架时落到同组相邻项，无相邻项则落到刷新入口。长列表遵守项目现有自算位移与焦点规则，不引入被项目禁用的滚动容器。

壁纸下载成功后提交选中引用。卡片下载成功后沿用现有复制内容到应用卡片文件的方式，保证离线显示；以后更换官方图片文件不会自动换掉已应用的卡片。

在线屏保采用独立的已加入 ID 集合。点击「加入轮播」时先下载，再持久化加入；「移出轮播」只改变参与状态，不删除原图。下载用于预览不等于加入轮播。APK 内置屏保现有默认参与和排除规则保持兼容。

所有选用动作执行前检查文件仍存在且完整，失败不提交新选择。页面关闭后取消未完成的选用意图；后台已完成文件可以留存，不能因迟到的回调改变用户后续选择。

## 6. 持久化、版本与离线

清单和原图放在应用私有持久目录，如 `files/gallery/`；缩略图放在 `cacheDir/gallery/`，允许系统回收。原图不放 cacheDir，避免离线资源被系统常规缓存清理删除。

壁纸新增 `gallery:<ID>` 引用；继续读取旧 `builtin:<ID>` 和用户文件名。解析时先识别受控前缀，禁止把远程 ID 当本地路径。

本地登记簿保存已下载资源的元数据和内容哈希；正在使用的壁纸及已加入屏保保存采用时的内容版本。清单更新不自动替换正在使用的内容，用户重新选用时才下载并采用新版本。

图库目录展示最新版本；同一 ID 内容发生更新时显示可更新状态。清单下架只取消新的在线发现；本地已下载项目仍可在在线图库的「已下载」部分查看、选用和移出屏保。未下载的下架资源无法继续选用。

首次离线打开显示内置和我的资源，在线组提示联网后可获取资源。已有同步历史时显示缓存目录，已下载项正常可用，未下载项提示联网下载。网络错误不使正常首页和屏保失效。

原图首期不自动淘汰，避免删除用户期望离线使用的图片；磁盘不足时下载失败并保留现有文件。提供删除未使用下载的操作；正在使用的壁纸或参与屏保的资源必须先取消使用。卡片已有独立副本，不依赖图库原图。

## 7. 下载与异常处理

下载写入独占 `.part` 文件，限制实际字节数；完成后核对 SHA-256、媒体格式和解码尺寸，再原子转正。重复请求共用同一内容哈希的任务。取消或失败删除本次临时文件，下次启动清理遗留临时文件，跳过本进程活动任务。

建议连接超时 10 秒、读取超时 15 秒、单次资源下载总超时 120 秒；所有网络、校验与图片解码在后台线程执行。首期不实现断点续传，失败后重新下载。

显示可理解的失败原因：网络不可用、下载失败、空间不足、资源文件异常。错误不覆盖有效目录、不覆盖完整旧文件、不改变用户当前设置。

HTTP 与 SHA-256 提供传输约束及文件一致性；不把哈希描述为独立于托管方的来源认证。首期使用受控域名和现有托管权限，无额外清单签名系统。

## 8. 图片处理和发布

壁纸与屏保原图沿用项目 HDR 规范，保留 Android 14 与 15+ 兼容元数据；卡片沿用现有 SDR 处理。缩略图从原图生成 SDR 版本，不能把缩略图作为最终应用内容。

发布工具应提供只生成和验证的模式，输出图片、缩略图、清单和新增/更新/下架差异。检查三语名称、包名、固定 ID、图片尺寸、来源许可和 HDR 格式。对上一版清单检查 revision 递增及身份冲突。

正式发布顺序：先上传不可变图片和缩略图，核对远端对象可用，再上传新 `index.json`。旧图片暂不删除，以便离线登记、在途下载及清单回滚；回滚发布内容应使用更高 revision。

资源发布独立于 APK 发布。用户已授权设计、计划及本地实施；云端上传、正式发布和推远程须另外获得用户确认，由 agent 执行。发布工具不属于本机常驻自动化，不配置定时任务或通知钩子。

## 9. 兼容与验收

旧设置无新字段时在线屏保加入集合为空；内置资源、用户图库与现有默认行为不变。恢复外观默认值沿用项目对图库取舍的保留规则，不能顺带清空下载或屏保加入集合。

必须验证：

- 清单解析、稳定 ID、三语显示、包名筛选、排序和非法路径拒绝。
- 首次离线、有缓存离线、304、刷新失败、同时打开两个页面。
- 下载成功、校验失败、取消、超时、空间不足及进程中断后清理。
- 下载失败保留原选择，页面关闭或用户改选后迟到任务不误应用。
- 壁纸持久化、卡片复制、自定义和系统屏保共用已加入资源。
- 内容版本变化不自动换图；下架不影响已下载使用；仅预览不加入屏保。
- APK 内置和我的图库回归，以及图库插入、下架和下载状态变化时遥控器焦点稳定。
- HDR 原图下载后的显示路径保真，缩略图没有误用于最终壁纸或屏保。
- 发布产物完整，图片先于清单发布，清单回滚可用。

实现阶段运行相关 JVM 测试、构建和模拟器交互验证；真机验证通过正式 APK 更新路径进行，是否发布须另行确认。
