# gtv 线实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `com.uniteduone.launcher.gtv` 这个并存包里,把 UnitedU 的全部界面换成 Google TV(launcherx 1.0.976298245)的外观,与现有 UnitedU 并排比较。

**Architecture:** 不新建工程,在同一份源码上加一个 `gtv` 分支 + 独立 `applicationId`。几何全部集中到一个**纯 JVM、可单测**的 `GtvLayout` 对象(与现有 `HomeLayout` 同形,便于对拍);Compose 层只读它。焦点画法从「tv-material `Card` 的库默认缩放 + 描边」改成「不缩放 + 自己在布局框外画描边」,这是本线风险最高的一处,单独成任务并先写最小例子验证。

**Tech Stack:** Kotlin 2.0.21 / AGP 8.7.3 / Compose BOM 2024.12.01 / androidx.tv-material / JUnit 4(28 个 JVM 单测已在 `app/src/test/`)。构建 `source scripts/env.sh && gradle --no-daemon assembleRelease`。

**Spec:** `docs/superpowers/specs/2026-09-20-gtv-line-design.md`(裁定依据 `docs/research/2026-09-20-gtv-vs-unitedu-comparison.md` §D;实测数值 `docs/research/2026-09-20-google-tv-launcherx-measurements.md`;对照图 `docs/screenshots/gtv/`)

## Global Constraints

- **焦点七条铁律**(`CLAUDE.md`「改这份界面前必须知道的七条」)对本线每一个任务都适用。新增的每个浮层必须在 CLAUDE.md 的**焦点责任表**里补一行,否则该任务不算完成。
- **不用任何可滚动容器**(`LazyRow`/`LazyColumn`/`horizontalScroll`/`verticalScroll`)。位移一律 `Modifier.offset` + `animateDpAsState` 自己算,行容器必须带 `Modifier.wrapContentWidth(Alignment.Start, unbounded = true)`,放在 `.offset(x = …)` 之前。
- **行尾裁切 ≠ 被量成 0 宽**:Google 的 peeking 卡宽 74 px 仍可聚焦,是正常参与布局后被屏幕边缘裁切。本线**不得**为实现 peeking 添加任何宽度约束。
- 密度 2.0(1920×1080 @ 320 dpi),A95L override 尺寸与密度逐位相同,dp 值 1:1 可用。
- **分支 `gtv`,worktree `.claude/worktrees/gtv`。不动 main。不推 GitHub,直到 Gordon 说「推」。**
- 模拟器命令一律带 `-s <序列号>`;**绝不向 A95L(192.168.1.22:38673)发按键 / 装包 / 改设置**,除非 Gordon 要求装包验收。
- **这台模拟器上按 `KEYCODE_DPAD_CENTER` 之前,先 `uiautomator dump` 读 `focused="true"` 的文案断言**(2026-09-20 盲按键误装过一个应用)。
- 验证用的 Google TV 对照实例是 AVD `unitedu-gtv`;本线自己的界面装到 AVD `unitedu-tv`(两台并存时注意内存,各 2–3 GB)。

```kotlin
package com.uniteduone.launcher

/** 卡片大小三档(B5-a:三个固定尺寸,不再是「每行几张」)。 */
enum class GtvCardSize { SMALL, MEDIUM, LARGE }

/**
 * gtv 线的全部几何,单位一律 dp(Float),**不含任何 Compose 类型**,便于 JVM 单测。
 * 数值出处:docs/research/2026-09-20-google-tv-launcherx-measurements.md(实测 launcherx 1.0.976298245)。
 * 与 [HomeLayout] 同形并存:main 线仍读 HomeLayout,本线只读这里。
 */
object GtvLayout {
    const val CONTENT_KEYLINE = 58f
    const val CARD_GAP = 20f
    const val HERO_HEIGHT = 192f
    const val TOP_BAR_TOP = 34f
    const val TOP_BAR_HEIGHT = 36f
    const val TOP_BAR_ICON = 32f
    const val TOP_BAR_ICON_GAP = 8f
    /** 行标题行盒高:实测 a11y (116,600)-(302,630) = 30 px = 15 dp。 */
    const val ROW_TITLE_LINE = 15f
    const val ROW_TITLE_TO_CARD = 12.5f
    /** 反推:125.5(实测行距)− 15 − 12.5 − 86.06(中档卡高)= 11.94,取整 12。 */
    const val ROW_GAP = 12f
    const val CARD_CORNER = 8f
    /** 焦点描边:画在布局框**外** FOCUS_OUTSET 处,粗 FOCUS_STROKE。不缩放。 */
    const val FOCUS_STROKE = 2f
    const val FOCUS_OUTSET = 5f
    const val CARD_TITLE_GAP = 4f
    const val CARD_TITLE_LINE = 16f

    fun cardWidth(size: GtvCardSize): Float = when (size) {
        GtvCardSize.SMALL -> 122f
        GtvCardSize.MEDIUM -> 153f
        GtvCardSize.LARGE -> 192f
    }

    fun cardHeight(size: GtvCardSize): Float = cardWidth(size) * 9f / 16f

    fun cardPitch(size: GtvCardSize): Float = cardWidth(size) + CARD_GAP

    /** 焦点卡钉在左基准线:行整体左移「索引 × pitch」。 */
    fun rowShiftX(focusedIndex: Int, size: GtvCardSize): Float =
        -focusedIndex.coerceAtLeast(0) * cardPitch(size)

    fun titleHeight(showTitles: Boolean): Float =
        if (showTitles) CARD_TITLE_GAP + CARD_TITLE_LINE else 0f

    fun rowPitch(size: GtvCardSize, showTitles: Boolean): Float =
        ROW_TITLE_LINE + ROW_TITLE_TO_CARD + cardHeight(size) + titleHeight(showTitles) + ROW_GAP

    fun rowShiftY(activeRow: Int, size: GtvCardSize, showTitles: Boolean): Float =
        -activeRow.coerceAtLeast(0) * rowPitch(size, showTitles)
}
```

**为什么 `ROW_GAP = 12f`**:实测中档行间距 125.5 dp = 15(行标题行盒)+ 12.5(标题到卡)+ 86.06(中档卡高)+ 0(不显示标题)+ 11.94。这 11.94 是反推出来的余量、取整成 12,不是另量到的值 —— 改卡高时它保持不变。**注意行标题是 15 dp 不是 30**:30 是像素,除以 density 2.0 才是 dp。

## Task 5:焦点画法 —— 不缩放 + 外扩 5 dp 描边

**这是本线风险最高的一处**:`Modifier.border` 画在布局框上,而我们要画在框**外** 5 dp;父容器一旦 clip 就看不见。**先写最小例子验证,再动 AppCard。**

**Files:**
- Create: `app/src/main/java/com/uniteduone/launcher/GtvFocusStroke.kt`
- Modify: `app/src/main/java/com/uniteduone/launcher/AppCard.kt:88-120`(border / scale)

**Interfaces:**
- Consumes: `GtvLayout.FOCUS_OUTSET`、`GtvLayout.FOCUS_STROKE`(Task 2)
- Produces: `fun Modifier.gtvFocusStroke(focused: Boolean, color: Color, corner: Dp): Modifier`

- [ ] **Step 1:写最小例子**

`GtvFocusStroke.kt`:

```kotlin
package com.uniteduone.launcher

import androidx.compose.ui.Modifier
import androidx.compose.ui.draw.drawBehind
import androidx.compose.ui.geometry.Offset
import androidx.compose.ui.geometry.Size
import androidx.compose.ui.geometry.CornerRadius
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.graphics.drawscope.Stroke
import androidx.compose.ui.unit.Dp
import androidx.compose.ui.unit.dp

/**
 * Google TV 的内容卡焦点画法(实测):**不缩放**,在布局框外扩 [GtvLayout.FOCUS_OUTSET] dp 处
 * 画一圈 [GtvLayout.FOCUS_STROKE] dp 的描边。
 *
 * 为什么不用 `Modifier.border`:border 画在布局框**上**,画不到框外。`drawBehind` 的画布不受
 * 布局框限制(只要父链上没有 clip),所以用负偏移把矩形撑出去。
 * **父容器不能 clip**:行容器已经有 `wrapContentWidth(unbounded)`,别再加 `clipToBounds`。
 */
fun Modifier.gtvFocusStroke(focused: Boolean, color: Color, corner: Dp): Modifier =
    this.drawBehind {
        if (!focused) return@drawBehind
        val out = GtvLayout.FOCUS_OUTSET.dp.toPx()
        val w = GtvLayout.FOCUS_STROKE.dp.toPx()
        val r = (corner.toPx() + out)
        drawRoundRect(
            color = color,
            topLeft = Offset(-out, -out),
            size = Size(size.width + 2 * out, size.height + 2 * out),
            cornerRadius = CornerRadius(r, r),
            style = Stroke(width = w),
        )
    }
```

## Task 9b:纵向节奏对齐(pre-Task-10 必做,2026-09-20 裁定 R11)

**为什么有这个任务**:Task 7 接上 `GtvLayout.rowShiftY` 之后实测出**每行 26.5 dp 的纵向漂移**(评审独立反算复核过)。漂移随行号线性累积,四行屏幕到最后一行差 ~79.5 dp,接近半张中档卡高 —— Task 10 的并排截图在这之上做没有意义,所以必须先修。

**漂移的四个来源**(逐项,评审从源码反算):

| 项 | `CategoryRow` 实际用的 | `GtvLayout.rowPitch` 假设的 | 差 |
|---|---|---|---|
| 行标题行盒 | `HomeLayout.ROW_TITLE_LINE` = 24 dp(`HomeScreen.kt:700`) | `ROW_TITLE_LINE` = 15 dp | 9 |
| 标题到卡的间距 | `HomeLayout.ROW_TITLE_GAP` = 8 dp(`HomeScreen.kt:698`) | `ROW_TITLE_TO_CARD` = 12.5 dp | −4.5 |
| 行外间距 | `HomeLayout.ROW_GAP` = 20 dp(`HomeScreen.kt:530`) | `ROW_GAP` = 12 dp | 8 |
| 焦点描边留白 | `2 × metrics.rowVerticalPad` = 14 dp(`Theme.kt:145` → `HomeScreen.kt:741`) | **公式里根本没有这一项** | 14 |
| 卡高 | 86.0625(`GtvLayout`) | 86.0625 | 0 ✅ |

合计 152.0625 − 125.5625 = **26.5 dp**。卡高那一项已经对上了,正是 R5 修好的部分。

**注意这是「新暴露」不是「早就存在」**:本任务之前 `metrics` 与 `shift` 都出自 `HomeLayout` 且吃同一个 `cardsPerRow`,按构造自洽、漂移数学上为零;`GtvLayout.rowShiftY` 在 Task 7 之前从未被渲染树调用过。
