# 首次安装旅程观察(2026-09-23)

**结论:在一台没有国行应用的干净机器上,新用户走完引导看到的是「一整屏深色 + 左上角两个小按钮 + 左下角一段指路文字」,而那段文字有三处与界面对不上(说「右上角」、说「已选中」、说选「编辑分栏」)。**从空首页加上第一个应用,需要按 5 次确定、翻一遍系统组件混杂的文字列表、再按 3 次返回。一张可以直接按的「＋」,首页上没有。

- 环境:`emulator-5558`(AVD `unitedu-tv-3`,Android 14 TV,1920×1080,系统语言 en-US,已装第三方 TV 应用只有 YouTube / Play Store / Cast moderator)
- APK:`c66fe8f`(main)22:38 构建的 release;装前 `adb uninstall`,确认 `/sdcard/Android/data/com.uniteduone.launcher` 不存在
- 无内置壁纸 → 纯深色背景
- 截图:`docs/screenshots/first-run-0923/`(总览 `overview.jpg`);下文每屏都标了文件名
- 只观察,没改代码

## 关键发现

1. **空首页的提示文案在三处上说错,照着做会走进死路**(A07、B07、B10、A08)。
   - 说「**右上角**的设置按钮」→ gtv 线换顶栏(`GtvTopBar`)后齿轮已经在**左上角**;右上角只剩时钟。
   - 说设置按钮「**已选中**」→ 只在进页那一刻成立。用户按一下右键,焦点就到了旁边的屏保按钮,文案不变;这时照着「按确定」会进屏保(一整屏黑 + 时钟,B09)。
   - 说选「**编辑分栏**」→ settings-shell 改版后,第一层菜单里没有这一项,它在「布局」里面(A08/B11)。只有副标题小字「编辑分栏、卡片大小与标题…」能提醒到用户。
   - 字符串 `home_empty_apps_hint`(三种语言)写于旧顶栏 / 旧齿轮菜单时期,后来两次改版都没有跟着改。
2. **在这台机器上,「继续」和「跳过」的结果完全一样:三个空行**。第 2 步只认内置的 11 个国行包名(`DEFAULT_LAYOUT`);装着的 YouTube 不在表里,所以显示「没有找到可自动放置的应用」(A02/B04)。用户看到的是两个按钮,选哪个结果都一样。第 1、3 步的「跳过」在代码里本来就等于「继续」(`onSkip = onNext` / `onFinish`),三步里只有第 2 步真的有选择。
3. **首页上没有「加应用」的入口,空状态和「只有一张卡」都是如此**。「＋」只在编辑分栏页里。从空首页到加上第一个应用的路径是:确定(齿轮)→ 确定(布局)→ 确定(编辑分栏)→ 确定(行尾「＋」,先弹行菜单 A11)→ 确定(添加应用)→ 在列表里往下翻 → 确定 → 返回 ×3。加完后首页只剩一张卡沉在左下角,上方约 2/3 空着,也不再有任何提示告诉用户「还可以加」(A17/B16)。
4. **「添加应用」列表是给开发者看的样子**(A12/A13)。纯文字,每项带包名,没有图标;12 项里 7 项是系统组件(Android Accessibility Suite、Calendar info、Dessert Case、Health Connect、Location Accuracy、VpnDialogs、Android TV Home)。用户真正想要的 YouTube 排在最底。
5. **引导第 1 步没有「这是什么」**(A01):一上来就是「选择语言」,没有一句话介绍 UnitedU 是什么、接下来会做什么。第 3 步的系统默认桌面页由系统提供(A04),刚进入时焦点**看不出落在哪一项**:第一次试的时候,「下移 + 确定」其实又选回了 Android TV Home(logcat:`Package is already a role holder … tvlauncher`),第二次等了一下再按下移才看到高亮(A04b)。

### 另外记下(次要,或属于模拟器问题)

- 选定 UnitedU 为默认桌面之后,系统落回了 Google TV 首页,HOME 键也仍然进 Google TV(A06)。这是 CLAUDE.md 里记过的模拟器怪癖(`KEYCODE_HOME` 不认 HOME 角色),`cmd role get-role-holders` 已确认是 UnitedU。A95L 上不适用。
- 编辑分栏在中文界面下行名仍是 `VIDEO` / `LIVE` / `MUSIC`(A10),与其他中文界面不统一。
- 默认卡片饱和度 30 / 亮度 75,让 YouTube 的横幅图看起来发灰(A14/A17)。第一次加上应用的人可能以为图坏了。
- 「布局」页左侧的实时预览在空桌面时只是一个空黑框,不显示空状态提示(A09)。
- 用户在引导里点「在系统设置中更改」时,引导会**先结束**再跳系统页(`endOnboarding(); switchHome()`)。系统页是半透明的,底下已经能看到空首页和那句错误的提示(A04)。
- 本应用没有「全部应用」抽屉。首页上没放的应用,只能通过系统设置之类的地方打开;Google TV 顶栏有 `Apps` 页可以兜底。

## 与 Google TV 的对比

`00-gtv-reference-empty-favorites.jpg`:Google TV 的「Favorite Apps」行为空时,**行本身仍然显示**,行里放一张可聚焦的「＋」卡,卡下写「Add app to favorites」。(本轮没点进去看选择界面长什么样。)另外顶栏有 `Apps` 页可以打开任何已装应用,所以首页即使空着,用户也不会被困住。

UnitedU 目前的空状态是**把空行整行藏掉**(`buildRows` 的 `.filter { it.apps.isNotEmpty() }`,注释写明这同时是焦点不变量),用一句文字代替。Google 的做法等于把编辑分栏页的「＋」直接放在首页上。

## 设计方向(只是建议,不实现)

1. **首页空行显示「＋」卡(照 Google Favorite Apps 做)**:空行不隐藏,显示行名 + 一张「＋ 添加应用」卡,确定后直接进选择器,选完原地出现卡片。非空行末尾可以选择也留一张「＋」。
   *取舍*:最直观,路径从约 8 步缩到约 3 步,也符合 gtv 线「照 Google 做」的原则。但 `buildRows` 的注释说明「空行不显示」同时是焦点不变量(上下键的 requester 只挂在非空行上),改动要重算首页的焦点账本和看门狗表,工作量最大、风险最高。
2. **专门做一个空状态页面(一次性,不碰行结构)**:`rows.isEmpty()` 时在首页中央放一块可聚焦的「欢迎卡」:一句话介绍 UnitedU、一个大按钮「添加第一个应用」(直接进添加应用选择器,选完落到第 1 行),下面再写一句「以后在 设置 › 布局 › 编辑分栏 里管理」。同时修正 `home_empty_apps_hint` 的三处错误。
   *取舍*:改动集中在「空」这一种状态上,焦点只需要多一个落点,风险低,正好回答 Gordon 说的「从来没看过那个页面」。但加了一张以后,「怎么再加」的问题照旧(见发现 3)。
3. **把第一个应用放进引导里完成**:第 2 步在内置分类表没命中时,不显示「没找到」,改成直接列出已装应用(带图标、过滤掉系统组件),让用户勾选几个放到第 1 行;「继续 / 跳过」只在第 2 步保留,第 1、3 步去掉重复的「跳过」。
   *取舍*:空首页基本不会再出现,选择器也顺便整理成有图标、无系统组件的样子(添加应用列表也能受益)。但偏离了 spec §0「只铺分类表命中的、零推荐」的原则:这里只是列出供用户勾选,不是推荐,原则的边界需要 Gordon 来定。另外 A95L 上本来就装着国行应用,那边「继续」可以正常填充,收益主要落在海外或纯净机型上。

**不管选哪个方向,都应该先修的**:`home_empty_apps_hint` 三种语言的「右上角 / 已选中 / 编辑分栏」三处。这是纯文案 bug,不涉及设计取舍。
