# 首页上下换行动效研究(2026-09-27)

**结论:突兀主要来自曲线形状,不是掉帧;另有一处不同步,只在行 1↔2 出现。** 现状的弹簧在 t = 0 就以最大加速度起步(80 ms 已走 33%,67 ms 到峰速)。而上下换行时整屏在跟着这条曲线变:131 dp 的位移,加上壁纸亮度掉到 46%,两者都按这条前重后轻的曲线走。左右换卡大多只有焦点放大,没有整页位移;即使有,也只动一行、不改壁纸。所以左右的手感没问题,上下却显得「一下子冲出去」。

**推荐:方案 A `tween(450 ms, FastOutSlowInEasing)` + 壁纸逐行插值。** 代码里只改一个常量:`GtvLayout.HOME_VERTICAL_MOTION = HomeVerticalMotion.TWEEN_450`,`WALLPAPER_DIM_PER_ROW` 会随之打开。分支默认仍是现状。

## 1. 现状测量

### 曲线(位移 131 dp,临界阻尼弹簧 k = 220)

| 指标 | 规格计算 | 模拟器实测(12 次换行中位数) |
|---|---|---|
| 到 50% | 113 ms | 125 ms |
| 到 95% | 320 ms | 345 ms |
| 停稳(99.7%) | 540 ms | 与规格一致(pts 抖动 ±30 ms,测不出更细) |
| 最大速度 | 715 dp/s,在 **67 ms** | 与规格一致 |
| 起步加速度 | t = 0 即最大 ≈ 2.9 万 dp/s²(前 30 ms 平均 1.8 万) | 与规格一致 |
| 80 ms 时进度 | 33% | 与规格一致 |

实测做法:追踪行 0 第 2 张卡(YouTube)的卡顶 y,用模板 SSD 加亚像素抛物线拟合;每帧用 `ffprobe` 取真实 pts。起步时刻按「最后一帧静止到第一帧运动之间」拟合。四个方案拟合出的时间伸缩系数中位数在 0.89–1.00 之间,说明模拟器按规格播放。

### 这 131 dp 期间同时在变的东西

| 东西 | 曲线 / 时长 | 起止(相对位移起步) | 与位移同步吗 |
|---|---|---|---|
| 整页位移 | 弹簧 k = 220 | 0 → 95% 在 320 ms | — |
| 壁纸 alpha(`wallpaperAlpha`) | 由位移逐帧换算:\|位移\| / 192 dp 线性,1 → 0.2 夹住 | 行 0→1:1 → 0.46,与位移同进度 | **行 0→1、1→0 同步**。**行 1→2 不同步**:位移走到 47% 时壁纸已暗到底(实测 95% 在 143 ms,位移要到 345 ms)。**行 2→1 不同步**:壁纸前半程不动,50% 在 185 ms(位移 50% 在 96 ms) |
| 行淡出(`homeRowAlpha`) | 由位移换算:卡顶在 110 → 70 dp 这 40 dp 的带里线性淡出 | 3 行、中档时根本碰不到(焦点在行 2 时行 0 卡顶在 161 dp) | 按空间位置遮罩,不是时间曲线,不算不同步。4 行及以上才出现 |
| 行图标焦点色 | 弹簧 k = 220(`rowIconFocusSpec`) | 与位移同起同止 | 同步 |
| 新焦点卡放大 | `tween(600, 减速)`,延迟 80 ms | 实测 10% / 50% / 90% 在 79 / 227 / 616 ms | 有意错开(R30/R37),位移收尾后还在慢慢放大 |
| 旧焦点卡收回 | `tween(400, AccelerateDecelerate)`,不延迟 | 实测 50% 在 171 ms | 有意错开(R79) |

「前 150 ms 里同时发生的事」:整页位移冲到峰速、全屏壁纸亮度掉一半(行 0→1:100 ms 内已掉了其中的 44%)、旧焦点卡开始收回、行图标换色、新一行从屏幕底边外冒上来。这一段集中了几乎所有的变化量,是「突兀」的来源。

### 掉帧迹象:没有(仅供参考)

在 `dumpsys gfxinfo … framestats` 里,纵向和横向两组的 UI 线程工作量都很小:动画 + 重组的中位数 0.2–0.8 ms、p90 0.6–5 ms,布局 + 绘制 p90 ≤ 1.1 ms。纵向位移每帧都会重组 HomeScreen,但这一项的开销也就是这个量级。模拟器帧时长(中位数 38–117 ms,每次跑都不一样)几乎全耗在 RenderThread 上,因为 swiftshader 是软件 GPU;纵向 29–96 ms、横向 32–47 ms,波动主要来自宿主机负载(同一时段 `dasd` 占 100% CPU,还有另一台模拟器在跑)。上下与左右之间没有看到结构性差异。真机没有测:A95L 在家人使用,本轮不碰。

## 2. 三个原型

| 方案 | 参数 | 80 ms 进度 | 到 50% | 到 95% | 停稳 99.7% | 峰速 | 起步加速度(前 30 ms 均值) | 实测 t95 |
|---|---|---|---|---|---|---|---|---|
| 现状 | spring k = 220 | 33% | 113 | 320 | 540 | 715 dp/s @ 67 ms | 18 500 dp/s² | 345 |
| **A** | tween 450, FastOutSlowIn (0.4, 0, 0.2, 1) | **10%** | 158 | **327** | 417 | 796 dp/s @ 136 ms | 3 300 | 316 |
| B | tween 550, CubicBezier (0.35, 0, 0.15, 1) | 9% | 172 | 390 | 507 | 690 dp/s @ 140 ms | 2 900 | 379 |
| C | spring k = 110 | 21% | 160 | 452 | 763 | 506 dp/s @ 95 ms | 10 500 | 443 |

时间单位均为 ms。实测一列来自每个方案 12 次换行的中位数。

- **C 的「壁纸 / 行淡出用同一条曲线」本来就成立**:壁纸 alpha 和行淡出都是每帧从位移动画值换算出来的,不是独立的动画;行图标用的是同刚度的另一根弹簧。所以 C 只把位移和行图标的刚度改成 110。能消掉的不同步只有上表那一处,也就是 192 dp 与 131 dp 的错位。
- **壁纸逐行插值(`WALLPAPER_DIM_PER_ROW`)**:把整页位移折成「第几行 + 行内进度」,在相邻两行的静止 alpha 之间线性插值。各行静止时的 alpha 与现状逐值相同(1 / 0.454 / 0.2),变的只是过程。实测打开后四种换行的「壁纸 50%」与「位移 50%」相差都不超过 21 ms(现状行 1→2 差 56 ms,行 2→1 差 89 ms,而且过程形状完全不同),见 `concurrent.png` 右栏与 `wallpaper-sync.mp4`。
- 录像 A/B/C 时逐行插值是关着的,单纯比曲线。推荐配置(A + 逐行插值)另装机录了一轮:四种换行壁纸 50% 与位移 50% 相差 0–3 ms,t95 298 ms。

### tween 的代价:连按两下会刹停一下

`animateDpAsState` 在动画中途换目标时:弹簧带着当前速度接着走;tween 从当前位置以**零速度**重新起步(`double-press.png`)。第 2 下落在 200 ms 时,A 的速度从约 480 dp/s 瞬间掉到 0,再冲到约 1040 dp/s;现状是 300 → 870 dp/s,中间连续。模拟器出帧太稀疏(连按那段只有 3–5 帧),录像里分辨不出来,所以这一点是按 Compose 语义算的,没有实测。只按一下(Gordon 描述的场景)时没有这个问题。

## 3. 推荐与理由

**A + 壁纸逐行插值**(`HOME_VERTICAL_MOTION = TWEEN_450`)。

1. **起步最软,但不变慢。** 80 ms 只走 10%(现状 33%),峰速推迟到 136 ms,位移不再「一下冲出去」。但到 95% 的时刻与现状几乎相同(327 vs 320 ms),而且 450 ms 就干净停住(现状的尾巴拖到 540 ms)。R38 那轮 owner 要的「阻尼感」和「不要太快」都不会退回去。
2. **B 太慢。** 95% 要 390 ms,100 ms 时只走 15%。按键后可感知的迟滞变长,容易从「突兀」变成「跟手慢」。
3. **C 治标不治本。** 起步加速度减半,但 t = 0 仍是最大加速度(形状没变,只是整体放慢),而且停稳要 760 ms。R38 的「停稳 500–700 ms」判据会被打破,尾巴也更拖。
4. **逐行插值与曲线无关,建议一起上。** 它只改行 1↔2 的壁纸过程,静止画面零变化。这处不同步在 A 下同样存在(实测 A 行 1→2 壁纸 95% 在 153 ms,位移 50% 才在 149 ms)。
5. **没动的:** 焦点放大延迟 80 ms(`FOCUS_AFTER_SHIFT_DELAY_MS`)与 600 ms 放大时长都是 owner 手感值,不在这次范围内。A 下 80 ms 时位移只走 10%,放大会比现状更早「领先」位移。如果电视上看着放大起得太早,再把延迟调到约 150 ms(A 在 150 ms 时走 46%)。

**需要在电视上确认的两件事:** ① 行 0→1 那一下是否不再突兀;② 快速连按两下时,那一下「刹停」能不能接受。如果不能接受,下一步可以做一个保留速度的软起步(例如两级串联弹簧:起步速度和加速度都为 0,换目标时速度连续),而不是退回单根弹簧。

## 4. 代码开关(分支 `try/vertical-motion`)

- `GtvLayout.HomeVerticalMotion { SPRING_220, TWEEN_450, TWEEN_550_SOFT, SPRING_110 }` 与 `HOME_VERTICAL_MOTION`,**默认 `SPRING_220` = 现状**。
- `GtvLayout.WALLPAPER_DIM_PER_ROW = HOME_VERTICAL_MOTION != SPRING_220`,现状时关。另有 `wallpaperAlphaPerRow` / `homeWallpaperAlpha`。
- `Theme.homeVerticalShiftSpec()` / `Theme.homeRowIconSpec()`:默认返回原来的 `browseShiftSpec()` / `rowIconFocusSpec()`。
- 只接了首页纵向位移、行图标色、壁纸 alpha 三处。左右位移、编辑页不动。
- 单测 `VerticalMotionTest`:钉住默认 = 现状;钉住 A/B/C 三个工厂的参数与上表的曲线数值;钉住逐行插值在各行静止时与现状逐值相同、每行内按进度线性、单调、不低于 0.2。
