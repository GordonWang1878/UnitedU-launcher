# Google TV 首页换行:新焦点行「晚一拍淡入」实测(2026-09-29)

> **现行数值见 gtv spec R129f**:新焦点行延迟 **220 ms**、**900 ms 匀速**淡入(`GtvLayout.ROW_ENTER_DELAY_MS` / `ROW_ENTER_FADE_MS`,`Theme.homeRowEnterSpec` 用 `LinearEasing`),旧焦点行不动(R129b 旧行淡出已回滚),行图层四边撑大 `APP_FOCUS_GLOW_DP`。下文的 140 ms / 250 ms `FastOutSlowIn` 是 R129 首版的实测记录,数字保留不改。

起因:Gordon 在 `unitedu-gtv` 上看 Google 首页,发现「页面的滑动」与「新一行进场」是两回事——新一行不是跟着整页刚性滑进来,而是晚一拍、淡入。

## 量法

- AVD `unitedu-gtv`(launcherx),**改用 `-gpu host` 重启**:原来 `-gpu swiftshader_indirect` 在宿主负载 10–20 时录屏只有 2–7 fps,量不了百毫秒级;host GPU 下 `screenrecord --size 960x540` 录到 784 帧 / 15 s(≈ 52 fps)。
- 按键序列:HOME → 下 ×4(顶栏 → hero 按钮 → Top picks → Your apps → Continue watching)→ 上 ×2,每下间隔 2.5 s。
- 每帧取 mp4 真实 pts;每一行用模板匹配(静止帧里截一块卡片,逐帧在纵向搜位移,相关系数 c 判「找没找到」,回归斜率 a ≈ 相对静止时的对比度 ≈ 透明度);YouTube 图标另用红色像素质心取纵坐标。坐标都是 960×540 录屏像素(= dp)。
- 录屏与图片不入库(画面里有 Google 账号头像 / 海报 / 广告,见 2026-09-29 推送事故),只留数字。

## 结果

**上键,新焦点行从上方进场(两次)**

| 过程 | 整页开始动 | 新焦点行第一次被找到 | 透明度 → 0.9 | 找到时离终点 | 移动结束 |
|---|---|---|---|---|---|
| Continue watching → Your apps | 11.711 | 11.844(a 0.20)**+133 ms** | 11.927(**+83 ms**) | 20 dp | ≈ 12.08(≈ 370 ms) |
| Your apps → Top picks | ≈ 14.244 | 14.394(a 0.15)**+150 ms** | 14.561(**+167 ms**,1.0 在 14.69) | 98 dp | ≈ 14.69(≈ 450 ms) |

- 进场前这一行在屏顶淡出带里,透明度 ≈ 0.07(看不见);**整页开始动后约 130–150 ms 内它一直看不见**,之后在走完最后一段路的同时淡入,约 100–300 ms 到满。
- 离开焦点、往下走的那一行全程可见,落到焦点行下方后停在 ≈ 0.57(Google 焦点行以下的行是压暗的)。

**下键,旧焦点行往上离场**

| 过程 | 旧焦点行 | 新焦点行 |
|---|---|---|
| Top picks → Your apps | 第一帧(+10 ms)a 0.50、+27 ms 0.22、+43 ms 起找不到——**几乎当场淡掉**,原位置留空;约 +140 ms 后在屏顶以 ≈ 0.2 → 0.06 重新出现(变成「上一行」的淡影) | 原本就露在屏底,跟着整页上移,ease-out,≈ 400 ms |
| Your apps → Continue watching | 跟着上移、透明度随之 1.0 → 0.21(≈ 300 ms),停在上一行淡影 | 原本就在屏上,上移 ≈ 176 dp |

## 与我们的差别

我们(R52 固定焦点线 + R53 顶部淡出 + R96 `tween(450, FastOutSlowIn)`):静止时焦点行以下的行在屏外;按下键时下一行从屏底**以满透明度刚性滑入**;行的透明度只由它当前的纵坐标决定(R53 淡出带 70–110 dp)。Google 的新焦点行在前 130–150 ms 不可见、随后淡入——视觉上是「旧的先走、位置空一下、新的再浮现」。

## 照做的数值(R129 首版;现行见文首 R129f)

- 换行时,**新焦点行**若在换行前不可见(屏外,或在顶部淡出带里透明度 < 0.5),对它单独叠一层时间驱动的透明度:**延迟 140 ms、`tween(250, FastOutSlowIn)` 从 0 到 1**,与整页 450 ms 位移同时开始计时;位移曲线不变。上键、下键都适用。
- 旧焦点行与其他行维持 R53 按位置淡出,不另加时间淡出。

## R129 实现与实测(2026-09-29)

**实现**(`HomeScreen` + `GtvLayout` + `Theme`):

- 常量 `GtvLayout.ROW_ENTER_DELAY_MS = 140`、`ROW_ENTER_FADE_MS = 250`、门槛 `ROW_ENTER_VISIBLE_MIN = 0.5`;规格 `Theme.homeRowEnterSpec()` = `tween(250, delayMillis = 140, FastOutSlowInEasing)`。
- 每行一个进场乘子(`mutableFloatStateOf(1f)`),乘到 `CategoryRow` 那层 `graphicsLayer { alpha = rowAlpha() * enterAlpha() }` 上,只在绘制阶段读。
- 触发:卡片的焦点回调里,落焦行 ≠ 原来的 `activeRow`、且不在还原途中、不在移动态(与 `tgtRow` 更新同一条件)。起点 `GtvLayout.rowEnterStart(按键这一刻的卡顶, 屏高, 当前乘子)`:在屏外 → 0;否则 `topFadeAlpha × 乘子`,≥ 0.5 返回 null(不淡)。起点在回调里同步写进乘子,再起一个协程 `withFrameNanos {}`(空等一帧,与位移同帧起算)后 `animate(起点 → 1)`。
- 连按:同一行的新一段淡入取消旧的那段;别的行的淡入照样跑完。移动态乘子一律按 1 画。
- 行图层上下各撑大 `APP_FOCUS_GLOW_DP`(R129f 起四边都撑大,行尾焦点卡原来在淡入期间右边被裁)(外层 `layout` 按原尺寸上报):alpha < 1 的离屏层以图层尺寸为界,不撑大的话焦点卡柔光在淡入期间被裁、到 1 那帧冒出来。

**实测**(`unitedu-tv` emulator-5560,`-gpu host`,`screenrecord --size 960x540 --bit-rate 20M` ≈ 60 fps,mp4 pts;纯黑壁纸 + 5 行占位布局,中档无标题。页面位置 = 行 0 Play 卡模板追踪,整段拟合 `FastOutSlowIn(450)` 得位移起点;行透明度 = 第 3 列占位卡可见行的 `Σ(帧 − 本行底色) / Σ(静止满透明参考 − 本行底色)`,底色逐行取空白区):

| 过程 | > 0.02 | 0.1 | 0.5 | 0.9 | 0.99 | 备注 |
|---|---|---|---|---|---|---|
| 规格(相对位移起步) | 162 | 185 | 228 | 299 | 357 | 390 满 |
| 下键 行 0 → 1(c4) | 165 | 186 | 229 | 302 | 362 | 0–160 ms 已露出屏底、透明度 0 |
| 下键 行 0 → 1(c5) | 164 | 185 | 227 | 303 | 362 | |
| 连按两下,行 1(5× 慢放,相对第一下) | 166 | 186 | 228 | 302 | 363 | 第二下 +154 ms 时乘子仍 0,之后不回退 |
| 连按两下,行 2(5× 慢放,相对第二下) | 178 | 195 | 238 | 308 | 369 | 两行最终 1.000 |

- **上键 行 1 → 0**:行 0 换行前在 310 dp(全亮),按规则不淡——全程 0.998–1.000;旧焦点行 ≥ 0.99。**我们的几何下单按上键不会触发 R129**(焦点线在屏幕下部,上一行静止时离淡出带很远);只在按住 / 连按、上一行还在淡出带里时触发。
- 整页位移:≈ 400–416 ms 进 0.5 dp、450 ms 停,与 R96 相同。
- 焦点(uiautomator):下 → 行 1 第一张、上 → 行 0、连按两下 → 行 2、快速下 ×4 → 行 4、快速上 ×3 → 行 1,落点全对,静止后各行全亮。移动态下键:进来的行从露出屏底起就是 0.97–1.00,不淡。
- 静止截图与改前逐像素相同(撑大图层不改布局)。

**量的时候踩到的**:

- 底色不是常数:纯黑壁纸下屏幕下半部分仍有 0 → 13(8 bit)的纵向底色,透明度要逐行扣本行底色、分母也扣同一行的底色,否则进场前(真透明度 0)会读成 0.15–0.17。
- 中途试过 `CompositingStrategy.ModulateAlpha`(不开离屏层,柔光不裁):它把 alpha 分别乘到卡片底色和上面的图(卡片自己的 R49 淡化层)上,实测表观曲线 ≈ `1 − (1 − α)^1.4`,整体快约 15 %(拟合时长 210–215 ms),5× 慢放同样——不是帧的问题,是合成方式,所以换成撑大离屏层。
- 淡入协程若不空等一帧,起点比位移早约一帧(不等时拟合 −11 ~ −14 ms,等了之后 +1 ~ +3 ms):位移的新目标要等下一帧重组,`animateDpAsState` 再下一帧才取起始时刻。
- 宿主负载高时 `screenrecord` 会整段丢帧、pts 挤在一起(一次 200 ms 空档、一次开头 150 ms 被吞),那几段直接作废重录;每段先查帧间隔再用。
