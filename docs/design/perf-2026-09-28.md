# 首页 GPU / 帧率优化(2026-09-28 夜间,A95L 实测)

分支 `perf/tv-gpu`。裁定 R110、R111。设备:Sony A95L(BRAVIA 4K AE1,MT5897,Mali-G57,4×Cortex-A73 跑 32 位,Android 14),
窗口 1920×1080(wm override)由 HWC 放大到 4K,60 Hz。

## 结论

- **首页的 GPU 大头是两道全屏绘制:壁纸与 R85 竖直渐变**,不是卡片。卡片的淡化离屏层(`gtvCardFade`)与透明度离屏层(R86)
  消融后量不出差别。R110 把这两道画进两张缓存图层,GPU 完成时间中位 17.3 → 12.7 ms(已编译时 4.3 ms),p90 20.0 → 15.0 ms,
  回到 16.7 ms 预算以内。
- **掉帧几乎都出在「按键那一帧」的 UI 线程**(Compose 重组),不在 GPU。刚装完的包没有 AOT 编译(`status=verify`),
  按键帧 UI 线程中位 14.6 ms、p90 23.5 ms;编译后 6.4 / 9.7 ms。R111 把每次按键重组的卡片数从 10–11 张降到 2–6 张,
  并去掉了换行动画里 HomeScreen 的逐帧重组。
- gfxinfo 的「GPU 百分位」在这台电视上**不是 GPU 的真实开销**:它是「交换缓冲 → GPU 完成」,GPU 一饱和就被上一帧排队钉在
  ~16.6 ms,而 Mali 的 DVFS 会把频率压到刚好跑满。要量开销得先让 GPU 在最高频饱和(见「方法」)。

## 方法

1. **帧数据**:`dumpsys gfxinfo <pkg> framestats` 每行一帧。自算:
   - GPU 执行时间 = `GpuCompleted[i] − max(SwapBuffers[i], GpuCompleted[i−1])`(扣掉排在上一帧后面等的时间);
   - UI 线程 = `SyncQueued − HandleInputStart`;按键帧 = `InputEventId ≠ 0`;
   - 掉帧 = 非按键帧里相邻两帧 `IntendedVsync` 间隔超过一个 vsync 的份数(按键帧的间隔可能是真空闲,不算)。
2. **4× 重绘探针**(只在临时构建里):首页那一层 `drawWithContent { repeat(4) { drawContent() } }`,让 GPU 在最高频饱和,
   这时 GPU 执行时间 ≈ 4 × 真实开销;消融某一层后的差值就是那一层的开销。1× 下 DVFS 会把省下来的算力换成降频,差值量不准。
3. **消融开关**(只在临时构建里,从 `/sdcard/Android/data/<pkg>/files/perf.txt` 读字母,`force-stop` 后重启生效),
   正式代码里没有任何开关。临时构建在本地分支 `perf/ablation-scratch`(不合并)。
4. **观感等价**:同一状态 `screencap`(raw RGBA,不经 PNG)逐像素比,掩掉时钟。

## 改动

### R110:壁纸 + R85 渐变画进两张缓存图层(`ce51226`)

原来每个像素 = `G·M + (1−G)·α·W`(黑底上画 alpha α 的壁纸 W,再盖 R85 渐变 G·M),每帧两道全屏着色。它对 α 线性,
α 恒在 `[0.2, 1]`,所以等于 `lerp(P_0.2, P_1, t)`,`t = (α − 0.2)/0.8`。`P_0.2`、`P_1` 各放进一个
`CompositingStrategy.Offscreen`(HWUI 硬件层,内容不变不重画),每帧只合成纹理:首行静止只合成一张,其余行静止也只合成一张,
换行中两张。渐变只在 `contentAlpha` 恰为 1、屏保与黑层都没在画时进图层,其余时候(待机 / 屏保淡入淡出、编辑页、无壁纸)
仍由首页画,叠放顺序不变;两边在绘制阶段读同一个 `HomeBackdropBridge`。

- 观感:首行静止最大差 1/255(整屏 8 个像素);行 1 静止最大 2/255(163 个像素 2/255,其余 ≤1);行 2 静止最大 1/255;
  编辑页 0 差;设置页预览框(首页缩小合成)内 ≤2/255,预览框底边两个圆角的抗锯齿像素最大 8/255(十来个像素)。
  都是 8 位量化的舍入差(图层里先舍入一次再合成)。
- 待机淡出实录(`screenrecord` 170 s,逐帧取底部亮度):淡出 1.2 s 平滑单调,交接那一帧没有跳变。
- 代价:两张 1920×1080 的硬件层,约 16 MB 显存;换壁纸 / 进出待机那一帧各重画一次。

### R111:位移动画不再每帧重组首页;左右移只重组得失焦点的卡(`e28a456`)

- 整页纵向位移原来在组合阶段读(`offset(y = shift)` + `SideEffect { onPageShift(shift) }`),换行动画 ~30 帧里 HomeScreen
  帧帧重组。改成 `offset {}` 布局阶段读(同样 `roundToPx`,位置逐像素相同),壁纸变暗改读首页交上来的动画 State(绘制阶段)。
- CategoryRow 的卡片焦点回调经 `rememberUpdatedState` 读 `focused` / `landingShiftsPage`,`focusAfterShift` 只传给本行焦点卡。
  按一次右键重组的卡 10 → 6 张,按一次下键 11 → 2 张(日志计数)。焦点账本、看门狗、还原效果一处未动。
- 观感:首行 / 行 1 / 行 2 静止截屏与 R110 逐像素相同。

## 没做的,以及原因

| 项 | 量到的开销 | 为什么没做 |
|---|---|---|
| 焦点柔光改画法 | 4× 探针下去掉省 ~1 ms/遍(R110 后仍是剩下的最大一块) | 30 圈 `drawRoundRect` 描边,每圈的光栅化范围是一条「圆角半径那么厚」的带子,大部分像素覆盖为 0。更省的画法(直边改矩形带、或 AGSL 距离场一次画完)会改变圈与圈接缝处的抗锯齿,做不到逐像素等价。几何每帧随缩放变,缓存也帮不上。只记录。 |
| 窗口从 HDR 色彩模式改回 sRGB | R110 前 ~1.3 ms/遍,R110 后量不出 | 窗口 `COLOR_MODE_HDR` 在这台电视上落成 8 位 Display P3;改回 sRGB 会改变索尼 HWC 看到的数据空间(色域映射可能变),观感风险。只记录。 |
| 卡片淡化 / 透明度离屏层 | 量不出 | 目标文件怀疑它是大头,实测不是(Skia 对这种小离屏层处理得很便宜)。不动。 |
| 壁纸 F16 → 8888、alpha 改 ModulateAlpha | 量不出 | 不动。 |
| 安装即编译 | 按键帧 UI 线程 14.6 → 6.4 ms(verify → speed-profile) | 这台 Android 14 的 ART 不认 APK 里内嵌的画像(`service-art.jar` 里没有嵌入画像的路径),侧载装完是 `verify`,要等后台 dexopt(夜里空闲)才编译。开发装包后可手动 `adb shell cmd package compile -m speed-profile -f com.uniteduone.launcher`;产品侧要么给安装流程带 `.dm`(需要一份真正覆盖本应用的 baseline profile),要么接受「装完第一天偏卡」。未改。 |
