# Gallery 共享资源改造提案

2026-10-11，用户选定先只做图片，在线视频标记暂未推出。按第一步范围单线程实施。

## 目标与建议分期

资源身份唯一、存储一次，使用场景独立。推荐第一步落实共享图片；第二步接入在线视频屏保。既有用户上传视频屏保继续可用，第一步不能宣称在线Gallery已支持视频。本次明确只实施第一步。

## 第一步：在线图库与素材源仓库

- 素材目录wallpapers/与screensavers/统一成images/；cards/独立，videos/作为后续素材位置。源图不改字节。pending-resources.json中的7张也只更新源路径，继续待兼容，不转换、不发布。
- 明确区分文件媒体类型（图片/视频）与用途列表（壁纸/屏保/应用卡片）。客户端不再以单一BuiltinKind决定在线资源身份；卡片用途独占且保留包名过滤。图片默认可用于壁纸和屏保，按用途过滤页面。
- 发布清单schemaVersion升级到2；新客户端继续读1，旧wallpapers/screensavers各映射为图片+原用途，cards映射为图片+卡片用途。未知版本/非法类型用途组合拒绝并保留旧缓存。
- 保留已有稳定ID（包括wall-前缀）、原图hash、采用记录与下载文件。前缀不代表用途，不能为了统一命名重新分配ID。旧目录历史kind转换时规范化身份，不能误判合法资源为ID复用。
- 同一id/hash在两页共用下载/缩略图与进度任务；一页取消不取消另一页仍需要的任务。采用设置仍分开：一个当前壁纸、一个屏保轮播集合。
- 两场景可分别采用同一ID的不同内容版本；任一仍引用的hash均受删除保护。刷新或下架不自动换图/撤销采用。仅变用途也不能破坏已经采用的可用旧版本。
- 原有聚焦稳定ID、可见范围缩略图、采样解码、失败重试、HDR字节保留、先图后清单发布规则继续保留。

## 本轮范围边界

推荐先处理在线Gallery、unitedu-gallery素材仓库、生成/发布工具、图片规范及首批产物。APK内置资源及用户上传资源保持现有目录和数据格式；没有为了本次共享把用户已有文件搬来搬去。它们仍可以之后按同一产品模型扩展共享，这不是“所有来源已统一”。如果用户要求同时统一内置/我的资源，应明确追加该范围后再细化迁移。

## 第二步：在线Gallery视频屏保

视频用途只能是屏保；壁纸页/卡片页不得出现视频。不能只把清单加入视频扩展名就宣布支持。需要同步完成：

- 本地工具探测真实视频轨、尺寸、时长/容器/编码，生成SDR封面与视频元数据；格式/体积/时长的在线分发限制另行定稿，不直接继承用户上传的500MiB上限。
- 客户端按媒体类型执行不同解码校验、显示时长/下载进度，支持取消/重试/校验失败，完成后才登记。
- 缓存原图文件目前采用hash.original命名，不能用扩展名判断在线视频；播放/预览必须携带媒体类型或使用可信可播放路径，兼容现有照片缓存。
- 屏保采用ID/hash并接入现有播放器，自定义和系统Dream均验证；继承现有最多60秒播放及失败跳过逻辑。壁纸不会增加视频播放能力。

## 兼容与首批4张资源

revision-1已生成、未发布，保持原样供追溯，不原地覆盖。新版工具以旧清单/历史为依据生成新revision，4张合格图片保留原ID与原图hash，用途改为壁纸+屏保，原图不转换。待兼容7张继续排除。源目录迁移前记录文件hash，迁移后对比；设置/旧缓存与版本采用在定向测试中验证。

## 验收边界

同一图片设壁纸后加入屏保不再请求原图；取消/移除一个用途不影响另一个；双方引用保护和分别固定旧版本正确；旧schema/缓存/历史仍能读；两页更新保焦；迁移11张源图hash不变；新版首批产物离线预演通过。无功能变更的文件不额外重复测试；新增功能只跑必要覆盖，最终一次全套构建。默认单线程实施，不追加代理层级。上线/远程推送仍需具体结果确认。
